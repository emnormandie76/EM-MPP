**À savoir pour les étapes suivantes**

9. **Lire les en-têtes avant d'ouvrir la base** : une page ou un layout qui appelle `getDb()` ou `getAuth()` doit d'abord passer par `requireUser()`, `requireAdmin()` ou `headers()`. Pendant `next build`, c'est ce qui arrête le pré-rendu avant l'ouverture de la base (PGlite des tests de bout en bout). Vérification : `DB_DRIVER=pglite PGLITE_DIR=.pglite-buildcheck npx next build` ne doit pas créer le dossier `.pglite-buildcheck` (vérifié à la fin de l'É6).
10. **Routes Better Auth ouvertes en HTTP** : seulement `/sign-in/email`, `/sign-up/email` et `/get-session` (`src/lib/auth/http-paths.ts`). Une nouvelle route nécessaire côté navigateur doit y être ajoutée, avec un test.
11. **Visites et session** : `VisitTracker` (dans `GameShell`, donc sur toutes les pages connectées, admin comprises) appelle `recordVisitAction` à chaque changement d'adresse, après l'affichage, sans revalidation. Cette Server Action lit la session, ce qui la renouvelle au plus une fois par jour (Better Auth ne peut pas le faire pendant le rendu d'une page).
12. **Pronos (É6)** : services dans `src/lib/services/predictions.ts`, verrous toujours dans l'ordre question (`FOR SHARE`) → ligne `user` du propriétaire (`FOR NO KEY UPDATE`) → prono (`FOR UPDATE`) (architecture §5.4). Un service qui écrirait sur les pronos doit suivre le même ordre. Lectures du joueur dans `src/lib/data/questions.ts` (`getOpenQuestionsForViewer`, `getQuestionsList`, `getQuestionDetail`, `getJokersLeft`) et `src/lib/data/home.ts` ; elles ne lisent que les lignes du joueur, sauf pour calculer ses points sur une question résolue. Composants du jeu dans `src/components/game/` (`Countdown` avec `role="timer"`, `data-testid="countdown"` et `data-urgent`, `QuestionCard`, `PredictionForm`, `StatusChip`, `HelpPanel`…) ; `Tabs` et `EmptyState` dans `src/components/ui/`. Contraste : `hot` sur le fond de page n'atteint que 4,2:1, d'où le compte à rebours compact en 20 px gras (grand texte) ; sur une ligne teintée `accent-soft`, les flèches ▲▼ ont un fond blanc.

En bout en bout, importer `test` depuis `e2e/fixtures.ts` (adresse client propre à chaque test, voir le §9.4 de l'architecture) ; `signIn()` attend le titre « Salut <nom> » de l'accueil. 24. **Conventions issues de la recette (01/10/2026)** :
   - **Grilles** : toute grille de mise en page porte `grid-cols-1` en plus de ses colonnes `lg:`/`sm:` (sinon, sous le point de rupture, la colonne implicite `auto` prend la largeur du plus long nom). `e2e/responsive.spec.ts` vérifie les pages avec un nom de 30 caractères (Thomas renommé, puis remis).
   - **Pages d'admin** : titre par `export async function generateMetadata() { return adminMetadata("…"); }` (`src/lib/auth/session.ts`), jamais par un `metadata` statique, que Next enverrait à un joueur avec la page 404.
   - **Messages de résultat** : `useFormAction` remet son état à zéro dès qu'une autre action commence sur la page ; un composant qui garde son résultat dans un `useState` utilise `useStaleResult(résultat, refDeSaZone)` (`src/components/ui/useStaleResult.ts`). Un message passé dans l'adresse se retire avec `DropSearchParams`.
   - **Formats** : `formatDateTime(date, now)` partout où la date peut être d'une autre année ; `formatNumber` sépare les milliers par U+00A0 ; `lowerFirst` pour une raison après un deux-points.
   - **Règles** : `PredictionScore.wentOver` (Juste Prix dépassé) ; `computeStandings` l'écarte de l'écart moyen. **Disparaît à l'É8c** avec le Juste Prix (v1.2). `buildStripChart(values, real, mean, width, viewerIndex)` réserve la place de l'étiquette « TOI ».
